# NOL 티켓(인터파크) 좌석 모니터 설계

작성일: 2026-07-20

## 목적
NOL 티켓(`tickets.interpark.com`) 특정 공연에서 목표 날짜/시간의 지정 좌석
(등급·구역·연석)이 예매 가능해지는지 감시한다. 예매창의 10분 세션 제한 안에서
날짜 토글로 좌석을 반복 확인하고, 발견 시 텔레그램 알림 + 예매창 홀드한다.
실제 선택·결제는 사람이 한다.

## 국립극장 모니터와의 관계
- 좌석 매칭(seats.py)·중복제거(state.py)·텔레그램(notifier.py) 코어는 공유한다.
- 국립극장은 단일 iframe에 좌석이 한 번에 보이는 수동 폴링이지만, NOL은 예매창
  진입·날짜 토글·타이머·재진입이 필요한 **능동적 네비게이션 상태머신**이라
  별도 드라이버·진입점을 둔다.

## 실행 방식
attach: 사용자가 `--remote-debugging-port=9222` Chrome에서 NOL 로그인 후,
프로그램이 attach해 자동 네비게이션한다. (국립극장과 동일 방식.)

## 구조
```
booking/
├── config.py          # [NOL] 섹션 로딩 추가 (기존 확장)
├── seats.py           # (재사용) 연석 매칭
├── state.py           # (재사용) 중복제거
├── notifier.py        # (재사용) 텔레그램
├── nol_driver.py      # (신규) 예매창 네비게이션: 진입·좌석읽기·일정변경·나가기
├── nol_monitor.py     # (신규) 10분 타이머 루프 진입점
└── targets.yaml       # NOL 타깃(등급·구역·열·연석) 추가
```

## 설정 (.env)
```
[NOL]
URL=https://tickets.interpark.com/goods
GOODS_ID=26005135
DATE=20260802
TIME=14:00
TOGGLE_DATE=20260805
TOGGLE_TIME=15:00
```
targets.yaml에 NOL 타깃을 사이트 구분과 함께 추가한다(형식은 실측 후 확정).

## 동작 흐름 (nol_monitor.py) — 사용자 6단계 반영
바깥 루프(예매창 재진입):
1. goods 페이지(`{URL}/{GOODS_ID}`) 접속.
2. 캘린더에서 DATE 선택 → 회차 TIME 선택 → `예매하기`(`a.sideBtn.is-primary`)
   클릭 → 새로 뜬 예매창으로 전환.
3. 9분 40초 내부 타이머 시작.

안쪽 루프(타이머 만료 전 반복):
4. 예매창에서 좌석 읽기 → 타깃(등급·구역·연석) 매칭.
   - 발견: 텔레그램 알림 + **홀드**(루프 중단, 예매창을 목표 좌석화면에 둔 채
     프로그램 대기; 사용자가 수동 선택·결제. Ctrl+C로 종료).
   - 없음: 일정변경 → TOGGLE_DATE/TOGGLE_TIME 선택 → 변경하기 → 다시 일정변경
     → DATE/TIME 선택 → 변경하기(좌석 리로드) → 4로.

타이머 만료 시: 이전페이지 → "사이트에서 나가시겠습니까?"에서 나가기 →
바깥 루프로 재시작.

## 좌석 판별 (실측 완료 — docs/discovery-nol.md)
예매하기 클릭 시 같은 탭이 `/onestop/seat`(최신 React SPA)로 이동. 좌석은 SVG
`<circle class="SeatMap_seatSvg__... js-seat">`.
- **가용**: `circle.js-seat` 중 `SeatMap_disabled__...` 클래스가 없는 것.
- **등급**: 채우기 색상(fill)으로 식별 — VIP `#7c68ee` / OP `#1ca814` / R `#17b3ff`
  / S `#fb7e4e` / A `#a0d53f` (매진 회색 `#edeff3`).
- **좌표**: circle `cx`,`cy`. 사람이 읽는 구역/열/번호 라벨은 **없음**.

## 매칭 모델 (확정: 등급 + 연석 + 좌표영역)
NOL은 구역/열 이름이 없으므로 좌표 기반으로 매칭한다.
- 대상 등급(색상)으로 가용 좌석 필터.
- (선택) 좌표 영역 제한: `cx`/`cy` 범위로 특정 구역만 한정. 미지정 시 전체.
- 연석: 같은 행(≈같은 `cy`, 허용오차 내)에서 `cx`가 근접(좌석 간격 임계 이내)하게
  이어지는 좌석을 인접으로 보고, N개 이상 이어지는 묶음을 찾는다.
- targets.yaml의 NOL 타깃: `grade`, `consecutive`, (선택) `region: {cx:[min,max], cy:[min,max]}`.

## 상단 컨트롤 (실측)
- 일정 카드 `[class*=scheduleCard]`에 선택 일시 + 남은 세션시간 표시
  (예 "2026.08.02(일) 2:00 PM ... 좌석 선택 시간 5:35") → 남은시간 파싱 가능.
- 일정변경: `button.SubHeader_layerDateButton__vncqy`.
- 예매창 나가기: 브라우저 뒤로가기 → 확인 다이얼로그(구현 시 확정).

## 발견 시 홀드
알림 후 안쪽/바깥 루프를 모두 중단하고, 예매창을 목표 좌석화면에 유지한 채
프로그램은 대기 상태로 멈춘다. 토글로 화면을 되돌리지 않는다.

## 위험 / 미해결
- **계정 제한 리스크**: 예매창 반복 진입·이탈과 잦은 날짜 토글은 인터파크 봇탐지에
  걸려 계정이 제한될 수 있다. 토글 사이 지연을 넉넉히 두고 반복을 절제한다.
  (사용자 본인 계정·본인 예매 목적 전제.)
- 10분 타이머·세션·팝업 구조 변화에 취약.
- **실측 필요(구현 전)**: 캘린더 일자 셀 선택자, 예매창 팝업 진입·좌석 DOM,
  일정변경 UI, 나가기 다이얼로그 — 사용자가 예매창 진입 후 read-only 실측.

## 비범위 (YAGNI)
- 자동 좌석 선택·결제 없음(알림 + 홀드까지).
- 다중 공연 동시 감시 없음.
